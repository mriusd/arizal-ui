Arizal

The exchange at arizal.xyz. Hybrid CLOB for timed BTC hit, above, and between markets. Matching is off chain. USDC, Yes/No share NFTs, and settlement live on the exchange contract. The UI talks only to HTTP and websocket /v1. The on-chain EIP-712 domain name is Arizal.

Exchange logic

Three kinds: hit, above, between. Four timeframes: daily, weekly, monthly, quarterly. Each market has a UTC-midnight expires_at. The node opens the next 7 expiries per kind × timeframe around Binance BTCUSDT. Strike grids come from markets.env (step size and rung count per asset × kind × timeframe; hit also has a reopen distance). Daily = next midnights; weekly = Mondays 00:00 UTC; monthly = 1sts; quarterly = Jan/Apr/Jul/Oct 1. Ids include timeframe, start time, and expiry so a resolved strike can reopen (e.g. btc-hit-<barrier>-up-daily-<start_ts>-<expires_at>).

  • Hit — Yes as soon as spot touches the barrier (up: spot ≥ barrier; down: spot ≤ barrier). At expiry without a touch, Yes if currently through, else No. After a Yes resolve, the same barrier+expiry waits until spot is far enough away (REOPEN_STEP_PCT% of the step, default 50%) before a new market opens.
  • Above — settles only at expiry. Yes if spot ≥ barrier.
  • Between — settles only at expiry. Yes if barrier ≤ spot ≤ barrier_high.

One share pays $1 if that side wins and $0 if it loses. On settle the book locks and resting orders cancel.

Book

The book is two bid lists, Yes and No. A Yes bid at p crosses a No bid at q when p + q >= 100. The trade prints at the maker’s price. The taker pays the complement, so the two sides together put up $1 per share. Prices are 1–99 cents. Same price is first-in, first-out. Size uses 6 decimals, the same scale as USDC (1 share is 1000000).

A buy can rest (GTC or GTD) or take immediately (FOK or FAK). A sell does not rest. It hits same-side bids. The seller is the taker. The resting bid is the maker and receives the shares.

Self-trades are rejected. Buys soft-reserve deposited USDC per market side. The engine does not hold keys or USDC. It writes an append-only tape. The trade admin later submits the match to the contract.

Money on a fill

Both wallets must have deposited collateral. Yes pays size × yesPrice / 100. No pays the rest of the bundle, plus any price improvement. If the two limits sum to more than 100, the extra is returned to the taker. The taker also pays the trading fee. The maker pays no fee. The node computes absolute takerFee / makerRebate (rebate is currently 0) and the trade admin passes them into settleFill / settleClose.

fee = shares × (trading_fee_factor / 1e18) × p × (1 − p)

p is the execution price in dollars. The fee is the same at 30¢ and 70¢ and is largest at 50¢. Net fees credit feeAccount collateral (defaults to the operator; setFeeAccount changes it). That account withdraws with ordinary withdraw. The local config uses 70000000000000000 (rate 0.07). A factor of 0 charges nothing.

Split, merge, close, redeem

Split locks n USDC and mints n Yes and n No ERC-1155 shares. Merge burns one Yes and one No and returns $1. Close sells shares into same-side bids; the trade admin calls settleClose, which moves the share NFT and the USDC. Redeem, after the market is resolved, burns the winning shares and credits $1 each. Losing shares pay nothing.

Session wallet

A wallet can call authorizeSession(wallet, expiresAt) (max 6 months; the UI uses 24h) so a browser session key may EIP-712-sign Orders. order.trader stays the main wallet. Withdraw, split, merge, redeem, and cancel still need the main wallet. Pass zero wallet to revoke. approveAgent grants the same session via a signed message.

Who can do what

  • Any wallet: deposit, withdraw, split, merge, redeem, settle, transfer share NFTs, authorize/revoke a session.
  • Trade admin only: createMarket, settleFill, settleClose. A fresh deploy sets this to the operator. settleClose has no user signature, so that key can move shares and collateral for closes.
  • Operator only: setTradeAdmin, setFeeAccount, setURI.

UI

Thin Vite + React client of /v1. Live markets, price, book, trades, account, and ledger ride the websocket; HTTP is for bootstrap, chart history, and wallet actions. If the socket drops, the header shows connection failed, reconnecting.

  • Wallet — header connect (injected wallet; optional WalletConnect). Switches to the UI chain before sending.
  • Markets — bar under the header (asset, kind, timeframe, strike, Yes/No ask, spot, % delta, expiry). Open the dropdown for the strike × expiry matrix (Hit / Above / Between × Daily / Weekly / Monthly / Quarterly). Yellow spot line; empty quotes are a gray dash. Cells are best Yes ask / best No ask; a click selects that market and side. Your Yes/No share sizes show as green/red pills under the quotes; open orders are tiny corner pills (left Yes, right No; blue buy, gold sell) with the order price. The same market pills (including timeframe) appear in Positions / Orders / Trades.
  • Chart — left column. Book mid history for the selected market id (5m / 1h / 1d / 30d). Yes green / No red (100 − Yes mid). Y-axis right, min–max mid rounded to 10¢, label and dim gray dotted grid at each 10¢, colored dotted mid line, time ticks on the X-axis. On hit markets, a history icon opens a hover list of prior resolves for that kind + barrier + expiry.
  • Order book — right of the chart. Yes / No toggle. Asks above bids (asks = other side at 100 − p). Split scroll with the spread centered. Price, size, USD; cumulative depth bars from the left. Click a row to set price; your resting levels are highlighted.
  • Trades — under the book. Engine fills with op, side, Yes price, size, time, status, tx.
  • Place order — right column, top. Buy / Sell, Yes / No, type (limit / market / merge / split), price, size, TIF. Size presets +1 … +50 accumulate. Buy shows cost and profit (payout − cost). Market buy is FAK at 99¢; market sell is FAK at any bid. Choices restore from the browser on refresh.
  • Account — under Place order. Deposit / withdraw, faucet (local), and a text link to authorize or revoke the session wallet.
  • Open positions / Closed positions / Orders / Trades / Funds — bottom row. Open positions: holdings with cost, mark value, pnl (credited as soon as a fill matches; unwound if settleFill permanently fails); Close / Redeem / Merge when applicable. Closed positions: exits from closes and redeems (shares, exit, pnl, tx). Orders: open buys (sells do not rest). Trades and Funds track pending → confirmed from chain logs.

Contract

The address in clearbook.toml is a single non-upgradeable Exchange (no proxy). Constructor (usdc, aggregator, operator) sets the EIP-712 domain to Arizal / 1 and tradeAdmin / feeAccount to the operator. Collateral and markets live on that address. Yes/No positions are ERC-1155 NFTs — one token id per market side (tokenId(marketId, side)). A contract change needs a new deploy (new address).

Websocket channels

Connect to /v1/ws. Most live data is push; subscribe only where noted.

ChannelSubscribePayload
markets yes (no market) Immediate full list { "channel": "markets", "markets": [...] }. Also pushed on lock/resolve.
market no (push on open) When a market is created: { "channel": "market", "op": "opened", "market": {…} } — one Market row (with quotes). Prefer this over waiting for a full markets resend; the full list is large and often lags out under load.
price yes Snapshot then each Binance tick (price, spot, barrier, ts).
book yes + market Immediate book snapshot; further snapshots at most once per market per 80ms.
tape / trades yes + market Immediate tape_snapshot / trades_snapshot, then live events/fills.
resolved yes + market Resolved markets that share kind + barrier (+ high) + expiry with market: { "channel": "resolved", "market", "strike", "expires_at", "markets" }. Pushed again when one of those resolves.
last_yes / quote no Fill mid and top-of-book updates without resending the full markets list.
account / ledger / holders no Collateral changes; positions/trades mirror (ledger also includes closed); holders. Filter account/ledger by trader.
closed_positions no Closed positions for one trader after close/redeem (and on each ledger push): { "channel": "closed_positions", "trader", "closed": [...] }. Same rows as GET /ledger/closed.
orders no Open orders snapshot after cancel-all: { "channel": "orders", "trader", "orders": [...] }. Same rows as GET /ledger/orders.

Merge and split are sent to the contract from the UI. The indexer records them when Split or Merged is logged. There are no POST /v1/positions/merge or /split writes to the database.
