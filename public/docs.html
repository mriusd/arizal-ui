Arizal

The exchange at arizal.xyz. Hybrid CLOB for timed BTC hit, above, and between markets. Matching is off chain. USDC, shares, and settlement live on the exchange contract. The UI talks only to HTTP and websocket /v1. The on-chain EIP-712 domain name is Arizal.

Exchange logic

Three kinds: hit, above, between. Four timeframes: daily, weekly, monthly, quarterly. Each market has a UTC-midnight expires_at. The node opens 7 future expiries per timeframe around Binance BTCUSDT on a $1,000 grid (ids include the timeframe, e.g. btc-hit-<usd>-up-daily-<expires_at>). Daily = next midnights; weekly = Mondays 00:00 UTC; monthly = 1sts; quarterly = Jan/Apr/Jul/Oct 1. Hit settles Yes early when spot touches the barrier; at expiry without a touch, No. Above settles only at expiry (Yes if spot ≥ barrier). Between settles only at expiry (Yes if barrier ≤ spot ≤ barrier_high). One share pays $1 if that side wins and $0 if it loses.

Book

The book is two bid lists, Yes and No. A Yes bid at p crosses a No bid at q when p + q >= 100. The trade prints at the maker’s price. The taker pays the complement, so the two sides together put up $1 per share. Prices are 1–99 cents. Same price is first-in, first-out. Size uses 6 decimals, the same scale as USDC (1 share is 1000000).

A buy can rest (GTC or GTD) or take immediately (FOK or FAK). A sell does not rest. It hits same-side bids. The seller is the taker. The resting bid is the maker and receives the shares.

Self-trades are rejected. The engine does not hold keys or USDC. It writes an append-only tape. The trade admin later submits the match to the contract.

Money on a fill

Both wallets must have deposited collateral. Yes pays size × yesPrice / 100. No pays the rest of the bundle, plus any price improvement. If the two limits sum to more than 100, the extra is returned to the taker. The taker also pays the trading fee. The maker pays no fee.

fee = shares × (trading_fee_factor / 1e18) × p × (1 − p)

p is the execution price in dollars. The fee is the same at 30¢ and 70¢ and is largest at 50¢. The local config uses 70000000000000000, which is a rate of 0.07. Collected fees sit in feePot until the operator calls withdrawFees. A factor of 0 charges nothing.

Split, merge, close, redeem

Split locks n USDC and mints n Yes and n No. Merge burns one Yes and one No and returns $1. Close sells shares into same-side bids. The trade admin calls settleClose, which moves the shares and the USDC. Redeem, after the market is Yes, burns the winning shares and credits $1 each. Losing shares pay nothing.

Who can do what

  • Any wallet: deposit, withdraw, split, merge, redeem, settleIfHit, settle.
  • Trade admin only: createHitMarket / createAboveMarket / createBetweenMarket, settleFill, and settleClose. A fresh deploy sets this to the operator. settleClose has no user signature, so that key can move shares and collateral.
  • Operator only: setTradeAdmin, setTradingFeeFactor, withdrawFees, and the proxy upgrade.

Contract

The address in clearbook.toml is a UUPS proxy (ArizalProxy). Collateral, shares, and markets live on the proxy. initialize(usdc, aggregator, operator) runs once. It sets the EIP-712 domain to Arizal / 1 and tradeAdmin to the operator. New storage is appended. It is not reordered.

Upgrading deploys a new Exchange implementation and the operator calls upgradeToAndCall. The proxy address does not change. See INSTRUCTIONS.md.

Orders are EIP-712 type Order(address trader,bytes32 marketId,uint8 side,uint8 price,uint256 size,uint8 orderType,uint8 tif,uint256 nonce,uint256 salt,uint256 expiresAt). side 0 is Yes and 1 is No. The domain name is Arizal, version 1, and the verifying contract is the proxy.

Base URL http://127.0.0.1:8080/v1. JSON in and out. The machine-readable schema is GET /v1/openapi.yaml. The routes below are what the node serves, including the ledger.
