Arizal

The exchange at app.arizal.xyz. Hybrid CLOB for timed BTC hit, above, and between markets. Matching is off chain. USDC, Yes/No share NFTs, and settlement live on the exchange contract. The UI talks only to HTTP and websocket /v1. The on-chain EIP-712 domain name is Arizal.

Exchange logic

Three kinds: hit, above, between. Four timeframes: daily, weekly, monthly, quarterly. Each market has an America/New_York (ET) midnight expires_at. The node opens the next 7 expiries per kind × timeframe around Binance BTCUSDT. Strike grids come from markets.env (step size and rung count per asset × kind × timeframe; hit also has a reopen distance). Daily = next ET midnights; weekly = Mondays 00:00 ET; monthly = 1sts ET; quarterly = Jan/Apr/Jul/Oct 1 ET. Ids include timeframe, start time, and expiry so a resolved strike can reopen (e.g. btc-hit-<barrier>-up-daily-<start_ts>-<expires_at>).

  • Hit — Yes as soon as spot touches the barrier (up: spot ≥ barrier; down: spot ≤ barrier). At expiry without a touch, Yes if currently through, else No. After a Yes resolve, the same barrier+expiry waits until spot is far enough away (REOPEN_STEP_PCT% of the step, default 50%) before a new market opens.
  • Above — settles only at expiry. Yes if spot ≥ barrier.
  • Between — settles only at expiry. Yes if barrier ≤ spot ≤ barrier_high.

One share pays $1 if that side wins and $0 if it loses. On settle the book locks and resting orders cancel.

Book

The book is two bid lists, Yes and No. A Yes bid at p crosses a No bid at q when p + q >= 100. The trade prints at the maker’s price. The taker pays the complement, so the two sides together put up $1 per share. Prices are 1–99 cents. Same price is first-in, first-out. Size uses 6 decimals, the same scale as USDC (1 share is 1000000).

A buy can rest (GTC or GTD) or take immediately (FOK or FAK). A sell does not rest. It hits same-side bids. The seller is the taker. The resting bid is the maker and receives the shares.

Self-trades are rejected. Buys soft-reserve deposited USDC per market side. The engine does not hold keys or USDC. It writes an append-only tape. The trade admin later submits the match to the contract.

Money on a fill

Both wallets must have deposited balance. Yes pays size × yesPrice / 100. No pays the rest of the bundle, plus any price improvement. If the two limits sum to more than 100, the extra is returned to the taker. The taker also pays the trading fee. The maker pays no fee and receives no rebate. The node computes absolute takerFee and passes it into settleFill / settleClose (no maker rebate).

fee = shares × (trading_fee_factor / 1e18) × p × (1 − p)

p is the execution price in dollars. The fee is the same at 30¢ and 70¢ and is largest at 50¢. Net fees and gas fees credit tradeAdmin balance (withdraw with ordinary withdraw). The local config uses 70000000000000000 (rate 0.07). A factor of 0 charges nothing.

Split, merge, close, redeem

Split locks n USDC and mints n Yes and n No ERC-1155 shares. Merge burns one Yes and one No and returns $1. Close sells shares into same-side bids; the trade admin calls settleClose, which moves the share NFT and the USDC. Redeem, after the market is resolved, burns the winning shares and credits $1 each. Losing shares pay nothing.

Session wallet

Enable 1-click trading has the main wallet sign (no tx) an EIP-712 ApproveAgent for a browser session key (24h; max 6 months). The signed auth is stored locally and sent with each place as agent_auth; settleFill verifies it on-chain. order.trader stays the main wallet. Withdraw, split, merge, redeem, and cancel still need the main wallet. Revoke deletes the browser key (no chain tx).

Who can do what

  • Any wallet: deposit, withdraw, split, merge, redeem, transfer share NFTs.
  • Trade admin only: createMarket, settleFill, settleClose. A fresh deploy sets this to the operator. settleClose has no user signature, so that key can move shares and balance for closes.
  • Oracle only: settle (defaults to the operator).
  • Operator only: setTradeAdmin, setOracle, disableOracleChanges, setURI.
